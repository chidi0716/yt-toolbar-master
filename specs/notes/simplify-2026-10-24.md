# 全專案精簡（2026-10-24，階段 11）

四個審查角度（重複實作、簡化、效能、修正層級）的結果，經規格方去重與篩選。**行為不變**；009、008 等規格的行為要求全部保留。

## 甲：小幫手（Go，`host/`）

- **H1 status 精簡（與乙的 X1 對應）**：`status` 結果改為只含擴充功能會讀的欄位：
  `hostVersion`、`ready`、`complete`、`components: [{name, found, version, path, source, error}]`（name 依序 helper、yt-dlp、deno、ffmpeg、ffprobe；`error` 為找到但無法執行時的錯誤代碼，否則空字串）、`defaultDir`、`namePresets`、`update`。
  刪除 `ytDlp`／`ffmpeg`／`deno` 物件（含 `manager`、`updateCommand`）、`missing`、`installCommand`（含 `InstallCommand` 與其測試）、`os`、`arch`、`installDir`。`ytdlp.UpdateCommand` 仍供 `updateYtDlp` 使用，保留。
- **H2 status 的工具版本快取**：在小幫手程序內快取工具的路徑與版本，以「路徑＋大小＋修改時間」為鍵；`updateYtDlp`、更新程序、安裝後失效。重複的 `status` 只做檔案 stat，不再啟動 4 個程序。
- **H3 `App.Status` 以表格取代三段相同的 goroutine**；命令表中 6 個無參數的處理函式改用 `noArgs(Backend.X)`。
- **H4 共用工具**：
  - 一個原子寫檔函式（暫存檔＋改名，含 Windows 改名重試），取代 `jobs.writeJSON`、`installer.writeJSONAtomic`、`updater.State.Save`、`installer/register.go` 的各自實作；
  - `commands.decodeArgs` 改用 `validate.DecodeStrict`（匯出），刪除 `commands/util.go`；
  - `errs.FromFS(err)` 統一 DISK_FULL／PERMISSION_DENIED 的判斷（`jobs/runner.go`、`installer/installer.go`）；
  - PID 鎖檔、`nopLogger`、一般檔案檢查等重複項一併合併。
- **H5 工作監看**：沒有被監看的工作時只等 `wake`，不每 300 ms 輪詢；`status.json` 改用精簡 JSON；`Init` 只讀一次工作資料夾並沿用到第一次 `List`。
- **H6 安裝時三個工具同時下載與核對**，安裝與輸出順序不變。
- **H7 移除時不再固定等待**：分離的移除程序等父程序結束後再刪除（不用 `--delay 2` 的固定秒數）。
- **H8 刪除死碼**：`errs.All`、`release.IsProjectReleaseURL` 等（以 grep 確認無引用）。

## 乙：擴充功能（TypeScript）

- **X1 status 精簡**：配合 H1 修改 `utils/native-protocol.ts` 的型別與解析；`componentState`／`componentVersion`／`componentInfo` 合併成一組以 `components` 為準的查詢；刪除 `COMPONENT_NAME` 對照表、`host-status.installCommand`、背景與內容腳本的重複解析，以及 `HostInfo` 中沒人讀的欄位（`channel`、`subtitles`、`autoCaptions`、`HostFormat.language`、`UpdateResult.upToDate` 等）。
- **X2 下載進度的傳遞**：進度只存在記憶體，工作狀態改變時才寫 `storage.session`；廣播合併為每秒最多一次（或只送改變的工作）；內容腳本只在按鈕進度或面板中的工作確實改變時重繪。工作清單在工具列第一次掛載時才建立（不在每個 YouTube 頁面啟動時送 `getJobs`）；可改用每個分頁一條 `runtime.connect` 連線取代儲存的分頁清單。
- **X3 重繪**：循環播放只在 `running`、`played`、`config` 改變時更新狀態；工具列按鈕各自 `useStore` 訂閱（如「更多」面板），刪除 `mount.tsx` 的整列重繪與 `features/viewing/index.ts` 的 `stores`／`toToggle` 清單。
- **X4 設定讀取**：`utils/settings.ts` 新增一個「讀取＋監看＋釋放」的設定 store 輔助，取代 `host-client.ts` 的四段監看、`setting-feature.ts`、`floating.tsx`、`quality.ts`、`host-background.ts` 的各自讀取；內容腳本啟動時以一次 `get([...])` 讀取多個鍵，`initI18n`、`enabled`、`toolbarLayout` 同時讀。
- **X5 新版本查詢**：內容腳本自己讀 `local:updateCheck`，只在 24 小時到期時才送訊息；背景一次讀兩個鍵；圖示標記沒變時不呼叫 `setBadgeText`。
- **X6 一鍵下載**：`getInfo` 與 `status` 同時開始；`startDownload` 的三個設定同時讀；面板模式改為以事件驅動的 reducer（`helperBecameReady`、`videoChanged`、`chooseOther`、`started`），取代 render 中修改的 ref；「準備中按改用其他畫質」改由背景在送出 `download` 前取消（`cancelQuick`），不再先建立再取消。刪除沒用到的 `source` 參數。
- **X7 小幫手狀態**：背景包裝 `client.request`，任何會改變狀態的指令自動清除快取（取代各處手動 `clear()`）；設定頁的安裝引導、元件狀態、更新結果改為掛載面板既有的 Preact 元件（`HostSetup`、安裝引導、`UpdateYtDlp`），刪除 `entrypoints/options/install-guide.ts` 與重複的狀態文字與輪詢；移除後以回應為準，不再固定等 3 秒。安裝引導面板開著時的偵測（008 FR-1）保留，只在一處實作。
- **X8 劇院模式與層級**：工具列提升改為頁面樣式規則（`html.ytm-cinema ytm-toolbar`），刪除 `decorateToolbarHost` 等；Esc 與點外面收起改為單一「可關閉層」堆疊（劇院、面板、編輯模式各自註冊）；刪除 `toggleCinema` 中重複的 `setSuspended`；z-index 集中成具名常數並以 CSS 變數引用。
- **X9 共用工具**（以下各合併成一份）：
  - 設定頁 DOM 輔助：`el`、`group`、`switchRow`、`selectRow`、狀態列、`formatDateTime` → `entrypoints/options/dom.ts`（嵌入資訊開關也改用 `switchRow`，會跟著其他分頁的變更更新）；
  - `isRecord`、影片 ID 與工作 ID 的驗證、`isLiveInfo`、影片與 MP3 的畫質標籤（含 HDR）、位元率檢查；
  - 影片長度 hook（含 `loadedmetadata`）、`LinkPanel` 改用 `useVideoData`；
  - 時間格式（`formatTime`、`formatEta`、`formatRange`、`timeTag` 共用一個拆分函式）、位元組格式（`formatSize`、`formatSpeed`）；
  - `sendToBackground`、`openSettings`、作業系統偵測、`<style id>` 的建立（`ensureStyle`）、複製到剪貼簿並顯示「已複製」；
  - 訊息型別以 `as const` 陣列推導聯集（`HOST_MESSAGE_TYPES`、`DIRECT_TYPES`、橋接請求）；`JobRecord` 以 `blankJob` 建立。
- **X10 頁面整理樣式只放開啟中的規則**（關閉的選項不放 `:has()` 規則）。
- **X11 縮圖**：檢查尺寸時保留取得的圖片，下載時沿用，不重複下載。
- **X12 新版本提醒**：`skippedVersion` 與 `handledVersion` 合併為 `dismissedVersion`（尚未發佈，不需要相容舊資料）。
- **X13 刪除死碼**：`Badge`、`qualityToApply`／`QualityCheck`（與其測試）、`FIXED_IDS`、`QUICK_KINDS`、`HostRequest` 等（以 grep 確認無引用）。

## 不採用

- 以「切回分頁時檢查」取代安裝引導的輪詢：008 FR-1 規定面板開著時定時檢查；改由 H2 讓每次檢查變便宜。
- Windows 檔案鎖的根本解法（共享刪除方式開檔）：本環境無法在 Windows 驗證，風險高於效益。
- `<html>` class 的兩套機制合併成一套：牽動 document_start 的頁面整理，效益不足。
- 浮動播放器捲動時的版面讀取：已限制為每畫格一次，影響小。
