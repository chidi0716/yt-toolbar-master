# 008 輕量安裝與自動更新

狀態：已確認（2026-10-23），實作見 plan 3.9、3.10、4.9、4.10 與 tasks 階段 8

## 目的

方便、輕量優先：讓一般使用者用**一行指令**裝好下載功能，之後自動保持最新；全程清楚告知裝了什麼（yt-dlp、ffmpeg、deno 與本專案的小幫手），不需要先安裝任何開發工具，也不需要另外的安裝 App。

## 為什麼是一行指令

- 不需要製作與維護安裝 App，也不需要付費的 Apple／Windows 簽章：以終端機（`curl`）或 PowerShell 下載的檔案不會被系統標記為「來自網路」，因此不會出現「未識別的開發者」或 SmartScreen 警告。
- 使用者看得到要執行的指令，安裝過程逐步印出正在做什麼，比雙擊不透明的安裝檔更容易建立信任。
- 不依賴 Homebrew／winget：直接從各工具的官方來源下載。

## 名詞

- **小幫手**：本專案的橋接程式在使用者介面上的名稱。介面上**可以也應該**直接寫出 yt-dlp、ffmpeg、deno 的名稱與用途，不隱藏。

## 功能需求

### 一、在擴充功能中引導安裝

- **FR-1**：小幫手尚未安裝時，影片與 MP3 面板顯示：
  - 說明：「下載影片與 MP3 需要在你的電腦上安裝 **yt-dlp**（下載影片的開源工具）、**ffmpeg**（合併影音與轉 MP3）與 **deno**（yt-dlp 需要的執行環境），以及本專案的小幫手（讓瀏覽器能使用它們）。全部約 150 MB（Windows 約 300 MB），只裝在你的帳號下，可以隨時移除。」
  - 依作業系統顯示**一行指令**與「複製」按鈕。
  - 三步驟圖文說明：
    - macOS：①按 ⌘＋空白鍵，輸入「終端機」並按 Enter ②貼上指令並按 Enter ③看到「完成」後回到這裡
    - Windows：①按開始鍵，輸入「PowerShell」並開啟 ②貼上指令並按 Enter ③看到「完成」後回到這裡
  - 「這個指令會做什麼？」展開：列出 FR-11 的步驟與下載來源，以及「先檢視腳本再執行」的方式。
  - 安裝完成後面板**自動偵測**並切換成可下載畫面（每隔幾秒檢查一次，只在面板開著時檢查；保留「重新檢查」按鈕）。
- **FR-2**：同樣的指令與說明也出現在設定頁的「下載」區與 README 的安裝章節。

### 二、一行指令安裝

- **FR-10**：指令從本專案 GitHub 的正式版本下載安裝腳本並執行：
  - macOS：在「終端機」執行的一行 `curl … | sh`
  - Windows：在 PowerShell 執行的一行 `irm … | iex`
- **FR-11**：安裝腳本依序完成，每一步印出簡短中英文說明與下載來源：
  1. 從本專案 GitHub 正式版本下載對應系統與晶片的小幫手，**核對檢查碼**（SHA256，來自同一個版本的元件清單）。
  2. 從 yt-dlp 官方 GitHub 正式版本下載 yt-dlp 單一執行檔，驗證官方檢查碼。
  3. 從 deno 官方 GitHub 正式版本下載 deno，驗證官方檢查碼。
  4. 下載 ffmpeg 與 ffprobe（來源見 plan 4.9，只使用公開、有檢查碼的來源；已有可用的 ffmpeg 時跳過並沿用）。
  5. 全部放在使用者資料夾內的一個專屬資料夾（macOS：`~/Library/Application Support/yt-toolbar-master/`；Windows：`%LOCALAPPDATA%\yt-toolbar-master\`），為 Chrome 與 Firefox（含 Zen）註冊。
  6. 印出「完成！回到瀏覽器即可下載」。
- **FR-12**：不需要系統管理員權限或密碼，不修改系統設定、不安裝到使用者資料夾以外的地方、不修改 PATH。
- **FR-13**：可以重複執行：已安裝且版本最新的部分跳過，其餘修復或更新。
- **FR-14**：任何一步失敗時，印出易懂的原因與解決方式；再執行一次即可從失敗處繼續。
- **FR-15**：使用者原本自己安裝的 yt-dlp、ffmpeg（例如 Homebrew）不會被修改；小幫手優先使用自己資料夾中的版本，設定頁標示目前使用哪一份。
- **FR-16**：保留現有的「下載 zip 再執行腳本」方式，放在 README 的「手動安裝」章節。

### 三、自動更新

- **FR-20**：小幫手在**使用者開始下載時**檢查更新，每 24 小時最多一次（沒有下載就不檢查、不連網；不使用常駐背景程式）。檢查與下載更新在背景進行，不延遲這次下載：
  - yt-dlp：使用 yt-dlp 自己的更新機制（`yt-dlp -U`，會驗證官方檢查碼）。
  - deno：官方 GitHub 正式版本，驗證官方檢查碼。
  - 小幫手本身：本專案 GitHub 正式版本，**核對檢查碼**後替換。
  - ffmpeg：不自動更新（很少需要），小幫手新版本可附帶更新。
- **FR-21**：更新只在沒有進行中的下載時替換（通常是這次下載結束後）；先下載到暫存、驗證、再替換，失敗時保留舊版本。
- **FR-22**：下載遇到 `YTDLP_OUTDATED`、`VERIFICATION_REQUIRED` 時，立即更新 yt-dlp（不受 24 小時限制），成功後自動重試該下載一次。
- **FR-23**：擴充功能（Firefox／Zen）：每個正式版本經 Mozilla 簽署（不公開頻道），manifest 指定本專案的更新網址，由瀏覽器自動更新。Chrome 版維持手動載入（Chrome 商店不允許 YouTube 下載工具）。
- **FR-24**：設定頁「下載」區新增：
  - 各元件版本與來源：小幫手、yt-dlp、ffmpeg、deno、擴充功能
  - 「自動更新」開關（預設開啟）、「立即檢查更新」、最近一次檢查的時間與結果
- **FR-25**：更新失敗不打擾使用者；連續失敗 3 次以上才在下載面板顯示一行提示。

### 三之一、擴充功能新版本提醒

- **FR-26**：只在**無法自動更新**的安裝方式顯示提醒：Chrome（手動載入）與 Firefox／Zen 的臨時附加元件（以擴充功能的安裝類型判斷，例如 `management.getSelf().installType` 為開發模式）。Firefox／Zen 簽署版由瀏覽器自動更新，不顯示提醒、也不查詢。
- **FR-27**：**擴充功能自己**查詢本專案 GitHub 的最新正式版本（版本號、標題、網址），**不需要小幫手**，只用觀看功能的使用者也會收到提醒（constitution 第 2 點例外）：
  - 時機：使用者打開 YouTube 影片頁時，每 24 小時最多一次；不在瀏覽器啟動時或背景定時查詢。
  - 不新增任何權限；不送出任何識別資訊；查詢失敗時安靜略過，下次再試。
  - 「不再提醒」後完全停止查詢。
- **FR-28**：提醒形式遵守 constitution 第 7c 點：
  - 在工具列下方顯示一張**不遮擋影片的小卡片**：「新版本 x.y.z 可以更新了」＋版本標題（一行），按鈕「前往下載」（在新分頁開啟該版本的 GitHub 頁面，頁面中有各瀏覽器的更新步驟）、「跳過這個版本」、「不再提醒」，右上角 ✕。
  - 只在合適的時機出現：影片頁載入完成後、分頁在前景、沒有展開的面板、不在全螢幕／子母畫面／編輯工具列、使用者沒有在輸入。劇院模式不影響（卡片在工具列下方，不會遮住影片）。條件不符時延後到條件符合時。
  - 確實被看到：卡片出現時以短暫的淡入吸引目光（不閃爍、不晃動、無聲）。收合計時只在分頁位於前景、且使用者有移動滑鼠或按鍵後才開始；累計 15 秒沒有互動才收合（滑鼠停在卡片上時暫停）。使用者離開電腦時卡片不會消失。
  - 收合後成為「更多」按鈕上的小圓點，一直保留到使用者處理（前往下載、跳過或不再提醒）；點「更多」可以在選單頂端看到同一則提醒。
  - 同一個版本每天（以使用者電腦的日期）最多以卡片形式出現一次；只按 ✕ 或自動收合而未處理時，隔天會再出現一次卡片。
  - 收合計時只累計「最近 5 秒內有操作」的時間；工具列不在畫面中（例如捲到留言區）時也延後。
- **FR-29**：「跳過這個版本」：記住該版本號，之後只在出現更新的版本時才再提醒。「不再提醒」：停止提醒與查詢；設定頁「關於」區可以重新開啟。✕：只關閉這次。
- **FR-29a**：有新版本時，擴充功能圖示顯示「NEW」小標記；設定頁「關於」區顯示目前版本、最新版本、最近一次查詢時間與「前往下載」。點「前往下載」「跳過這個版本」「不再提醒」或更新到最新版本後，標記消失。工具列被關閉時仍會查詢，只更新圖示標記。
- **FR-29b**：工具列被關閉時不顯示卡片；下次工具列出現時再依 FR-28 顯示。（擴充功能圖示在 Chrome 可能被收在拼圖選單中，因此不能只靠圖示標記。）
- **FR-29c**：小幫手的「更新失敗」「建議安裝元件」等提示同樣遵守 constitution 第 7c 點。

### 四、移除

- **FR-30**：設定頁「移除下載功能」：確認後由小幫手刪除專屬資料夾（含 yt-dlp、ffmpeg、deno、記錄檔）與瀏覽器註冊；已下載的影片不受影響。
- **FR-31**：README 提供一行移除指令（給擴充功能已移除的情況）。

### 五、透明度

- **FR-40**：README 與設定頁連結一份白話的說明：會安裝什麼、各自的用途與官方網址、放在哪裡、會連到哪裡（YouTube、GitHub）、不收集任何資料、如何移除。
- **FR-41**：專案採用 MIT 授權（`LICENSE`），並列出 yt-dlp、ffmpeg、deno 的授權。

### 六、發佈流程（維護者）

- **FR-50**：建立版本標籤後，GitHub Actions 自動：建置擴充功能與小幫手、產生元件清單（含每個檔案的 SHA256）、送 Mozilla 簽署、建立 GitHub Release（含安裝腳本、小幫手、擴充功能套件）、更新 Firefox 的更新資訊檔。
- **FR-51**：本專案**不使用自己的簽章金鑰**（2026-10-23 決定）：能修改 Release 的人也能取得 GitHub Secrets 中的金鑰，額外保護有限。改為：
  - 所有檔案只從本專案 GitHub 的固定版本網址以 HTTPS 取得，並核對元件清單中的 SHA256；
  - repo 開啟 GitHub 的「不可變更版本」（immutable releases），版本發佈後檔案不能再被修改或替換。
- **FR-52**：Mozilla API 金鑰只存在 GitHub 加密 Secrets。**尚未設定時發佈流程照常完成**：略過 Firefox 簽署，附上未簽署的 Firefox 套件（只能以臨時附加元件載入），不產生 `updates.json`，並在 Release 說明註明。README「維護者」章節寫明第一次設定步驟。

## 安全需求

- **SR-1**：安裝腳本與小幫手只連到：本專案 GitHub、yt-dlp 與 deno 官方 GitHub、FFmpeg 的指定來源、YouTube（由 yt-dlp 連線）。
- **SR-2**：所有檔案（本專案與第三方）都必須符合元件清單中的 SHA256；元件清單只從本專案 GitHub 以 HTTPS 取得；第三方工具的 SHA256 在發佈時與官方公布的檢查碼比對；驗證失敗一律拒絕並保留舊版本。
- **SR-3**：擴充功能本身只連 YouTube、小幫手，以及 FR-27 的本專案版本查詢（constitution 第 2 點）；其餘新增的網路連線只限安裝腳本與小幫手的更新。

## 驗收條件

- [ ] 一台全新的 Mac（只有 Zen，沒有 Homebrew）：照面板說明貼上一行指令，完成後面板自動變成可下載，成功下載 1080p 影片與 MP3；全程沒有系統安全警告。
- [ ] 一台全新的 Windows 11 同上。
- [ ] 已用 Homebrew 安裝 yt-dlp 的 Mac：執行指令後原本的 Homebrew 版本不受影響。
- [ ] 安裝指令執行第二次不會出錯，只更新需要更新的部分。
- [ ] 把 yt-dlp 換成舊版並觸發 `YTDLP_OUTDATED`：自動更新並重試成功。
- [ ] 竄改下載的小幫手（檢查碼不符）：拒絕安裝或更新。
- [ ] 尚未設定 Mozilla 金鑰時建立版本標籤：Release 照常建立，附未簽署的 Firefox 套件。
- [ ] 發佈新版本後，Firefox／Zen 的擴充功能自動更新；小幫手與 yt-dlp 在 24 小時內自動更新。
- [ ] 設定頁「移除下載功能」後，專屬資料夾與註冊都被移除，已下載的影片還在。
- [ ] 設定頁正確顯示各元件版本、來源與最近一次檢查結果。
- [ ] 一天內多次下載只檢查一次更新；沒有下載的日子不連網。
- [ ] Chrome 版（**沒有安裝小幫手**）：發佈新版本後，下一次開啟影片頁（距上次查詢超過 24 小時）時出現提醒卡片；劇院模式下也會出現；全螢幕或面板展開時延後，結束後出現；使用者離開電腦時卡片不會收合，回來後 15 秒沒有互動才收合成「更多」上的小圓點，小圓點保留到處理為止；只按 ✕ 時隔天再出現；「前往下載」開啟對應的 GitHub 版本頁面；「跳過這個版本」後同版本不再提醒、更新版本出現時再提醒；「不再提醒」後不再顯示，設定頁可重新開啟。
- [ ] Firefox／Zen 簽署版不顯示提醒卡片。
